# Воспроизведение музыки из Telegram с автоматическим обновлением очереди

**Статус**: 📋 Запланировано  
**Приоритет**: 🟡 Средний  
**Категория**: Новые функции

## Проблема

Когда плейлист уже играет в Яндекс.Музыке, новые треки, добавленные после начала воспроизведения, не попадают в очередь, т.к. приложение загрузило плейлист со старой revision.

## Описание

Исследовать возможность воспроизведения музыки прямо из Telegram через встроенный плеер. Это решит проблему обновления очереди, т.к. плеер будет контролироваться ботом и сможет автоматически обновляться при изменении плейлиста.

## Новое направление решения

### Telegram Web Apps / Mini Apps

Telegram предоставляет возможность создания веб-приложений (Web Apps / Mini Apps), которые открываются внутри Telegram в отдельном окне. Это позволяет создать полноценный музыкальный плеер с UI.

**Преимущества:**
- ✅ Плеер контролируется ботом — можно обновлять очередь в реальном времени
- ✅ Воспроизведение на заблокированном экране поддерживается Telegram
- ✅ Удобный UI в отдельном окне (как кнопка "Open" в BotFather)
- ✅ Интеграция с ботом через Telegram Web App API

### Возможные подходы

1. **Telegram Web Apps (Mini Apps)**
   - Создать веб-приложение с музыкальным плеером
   - Открывать через кнопку в боте или через BotFather (кнопка "Open")
   - Использовать Telegram Web App API для взаимодействия с ботом
   - Плеер может получать обновления плейлиста в реальном времени

2. **Telegram Bot API sendAudio**
   - Отправка аудиофайлов через `sendAudio`
   - Встроенный плеер Telegram с поддержкой заблокированного экрана
   - Ограничение: нужно скачивать и отправлять файлы (проблема с правами на контент)

3. **Гибридный подход**
   - Web App для управления и UI
   - sendAudio для воспроизведения (если возможно получить прямые ссылки на треки)

**Как работает стриминг vs скачивание:**

**Стриминг:**
- Воспроизведение аудио напрямую из интернета без полного скачивания
- Данные передаются в реальном времени по частям (чанками)
- Можно начать воспроизведение сразу, не дожидаясь полной загрузки
- Требует постоянное подключение к интернету
- Поддерживает HTTP Range Requests (запросы части файла)

**Скачивание:**
- Полная загрузка файла на устройство
- Файл сохраняется локально и может воспроизводиться офлайн
- Требует время на полную загрузку перед воспроизведением

**Может ли ссылка для скачивания подходить для стриминга?**
- ✅ Да, если ссылка поддерживает HTTP Range Requests (заголовок `Accept-Ranges: bytes`)
- ✅ Медиаплееры могут запрашивать части файла (например, первые 1MB для начала воспроизведения)
- ✅ Если в браузере при вставке ссылки открывается встроенный плеер и начинается воспроизведение - это хороший признак поддержки стриминга

**Как проверить ссылку на пригодность для стриминга:**
1. **Вставить ссылку в браузер** - если откроется плеер и начнется воспроизведение, ссылка подходит для стриминга
2. **Проверить HTTP заголовки:**
   - `Accept-Ranges: bytes` - поддержка Range Requests (необходимо для стриминга)
   - `Content-Type: audio/*` - тип контента должен быть аудио
   - `Content-Length` - размер файла
   - Статус код должен быть 200

#### Проблема с get_direct_link()

При выполнении скрипта обнаружено, что метод `get_direct_link()` возвращает **XML с метаданными**, а не прямую ссылку на аудиофайл.

**Структура XML:**
```xml
<download-info>
  <host>api.music.yandex.net</host>
  <path>/U2FsdGVkX1-...</path>
  <ts>19af86afdfc</ts>
  <region>-1</region>
  <s>qDngoKnP3s7YO549flVo8jU7KUCoMojxUeUSrXdp0VU</s>
</download-info>
```

**Что это означает:**
- API возвращает метаданные для построения URL, а не готовую ссылку
- Нужно извлечь `host` и `path` из XML или из атрибутов объекта
- Возможно, нужны дополнительные параметры (`ts`, `region`, `s`) для авторизации

**Решение:**
- ✅ Обновлен скрипт для обработки XML-ответа
- ✅ Добавлена функция `_extract_url_from_xml_or_build()` для извлечения URL из XML
- ✅ Добавлена логика построения URL из атрибутов `host` и `path`
- ⏳ Требуется тестирование: проверить, работает ли построенный URL для стриминга

### Content-Type: не критическая проблема для Mini Apps

**Дата**: 2025-12-07  
**Статус**: ✅ Решение найдено

#### Обнаруженная особенность

**Обнаружено:**
- ✅ URL успешно построен из `host` и `path`
- ✅ URL поддерживает HTTP Range Requests (`Accept-Ranges: bytes`)
- ✅ URL возвращает файл (статус 200)
- ⚠️ **Content-Type = `application/octet-stream` вместо `audio/mpeg`**

**Пример URL:**
```
https://api.music.yandex.net/get-mp3/16d0419844a2c86679dcbc4bd105e1c4/19af87de6f5/U2FsdGVkX1_...
```

**HTTP заголовки:**
- `Content-Type: application/octet-stream` ⚠️
- `Content-Length: 9085387` ✅
- `Accept-Ranges: bytes` ✅

#### Решение: Fetch API + Blob URL для постепенной загрузки

**Важное открытие:** Content-Type **не является критической проблемой** для Mini Apps, если использовать правильный подход с JavaScript Fetch API и Blob URLs.

**Как это работает:**

1. **Fetch API с поддержкой Range Requests:**
   ```javascript
   // Загружаем первые байты для начала воспроизведения
   const response = await fetch(url, {
     headers: {
       'Range': 'bytes=0-1048576' // Первый 1MB
     }
   });
   const blob = await response.blob();
   ```

2. **Создание Blob URL для воспроизведения:**
   ```javascript
   // Создаем Blob URL с явным указанием типа
   const blobUrl = URL.createObjectURL(new Blob([blob], { type: 'audio/mpeg' }));
   
   // Используем в Audio элементе
   const audio = new Audio(blobUrl);
   audio.play();
   ```

3. **Постепенная загрузка по частям:**
   ```javascript
   // Загружаем трек по частям (чанками) по мере необходимости
   // Браузер автоматически запрашивает нужные части через Range Requests
   audio.addEventListener('progress', () => {
     // Можно отслеживать прогресс загрузки
   });
   ```

**Преимущества подхода:**
- ✅ **Content-Type не важен** — мы явно указываем тип при создании Blob
- ✅ **Постепенная загрузка** — браузер автоматически запрашивает нужные части через Range Requests
- ✅ **Быстрый старт** — воспроизведение начинается после загрузки первых байтов
- ✅ **Работает везде** — стандартный Web API, поддерживается всеми современными браузерами
- ✅ **Без прокси** — не нужен дополнительный сервер, данные идут напрямую от Яндекс.Музыки
- ✅ **Эффективно** — загружаются только нужные части трека

**Альтернативные решения (если понадобятся):**

**1. Прокси-сервер (если Fetch API не подойдет)**
- Создать прокси-эндпоинт в боте для установки правильного Content-Type
- ⚠️ Требует дополнительную нагрузку на сервер
- ⚠️ Может быть медленнее из-за двойной передачи данных

**2. HTML5 Audio с явным указанием типа (простой вариант)**
```html
<audio controls>
  <source src="URL" type="audio/mpeg">
</audio>
```
- ⚠️ Может не работать во всех браузерах при `application/octet-stream`

**Рекомендация:**
Использовать **Fetch API + Blob URL** как основное решение. Это современный, эффективный подход, который решает проблему Content-Type и позволяет реализовать постепенную загрузку контента по частям.

#### Пример реализации для Mini App

```javascript
// Класс для работы с аудио через Fetch API
class AudioStreamPlayer {
  constructor(url) {
    this.url = url;
    this.audio = null;
    this.blobUrl = null;
  }

  async load() {
    try {
      // Загружаем первые байты для быстрого старта
      const response = await fetch(this.url, {
        headers: {
          'Range': 'bytes=0-1048576' // Первый 1MB
        }
      });

      if (!response.ok && response.status !== 206) {
        throw new Error(`HTTP error! status: ${response.status}`);
      }

      // Получаем Blob
      const blob = await response.blob();
      
      // Создаем Blob URL с правильным типом
      this.blobUrl = URL.createObjectURL(
        new Blob([blob], { type: 'audio/mpeg' })
      );

      // Создаем Audio элемент
      this.audio = new Audio(this.blobUrl);
      
      // Браузер автоматически будет запрашивать остальные части через Range Requests
      return this.audio;
    } catch (error) {
      console.error('Ошибка загрузки аудио:', error);
      throw error;
    }
  }

  async play() {
    if (!this.audio) {
      await this.load();
    }
    return this.audio.play();
  }

  pause() {
    if (this.audio) {
      this.audio.pause();
    }
  }

  destroy() {
    if (this.blobUrl) {
      URL.revokeObjectURL(this.blobUrl);
      this.blobUrl = null;
    }
    if (this.audio) {
      this.audio = null;
    }
  }
}

// Использование
const player = new AudioStreamPlayer(trackUrl);
await player.play();
```

**Ключевые моменты:**
- Fetch API автоматически обрабатывает Range Requests для загрузки нужных частей
- Blob URL позволяет указать правильный Content-Type независимо от заголовков сервера
- Браузер кэширует загруженные части автоматически
- Можно отслеживать прогресс загрузки через события Audio API
