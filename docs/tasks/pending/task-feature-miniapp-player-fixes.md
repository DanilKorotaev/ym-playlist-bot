### 3. Рефакторинг miniapp/api/routes.py

**Задача:** Проанализировать и улучшить структуру создания зависимостей (БД, client_manager).

**Статус:** ✅ Выполнено

**Что было сделано:**
- [x] Проанализирована текущая реализация создания зависимостей
- [x] Изучены паттерны создания зависимостей в FastAPI (Dependency Injection)
- [x] Реализована улучшенная архитектура:
  - Использованы FastAPI Depends для dependency injection
  - Использован app.state для хранения зависимостей
  - Добавлены lifespan events для управления жизненным циклом
  - Упрощен код инициализации (убраны глобальные переменные)
- [x] Задокументирован выбранный подход (в коде через docstrings)

**Реализованные улучшения:**

1. **Убраны глобальные переменные** - все зависимости хранятся в `app.state`
2. **Использованы FastAPI Depends** - чистый dependency injection через функции `get_db()`, `get_client_manager()`, `get_playlist_service()`
3. **Добавлены lifespan events** - инициализация и очистка зависимостей происходит в `lifespan()` функции в `server.py`
4. **Упрощена логика создания зависимостей**:
   - Для PostgreSQL: создается отдельный экземпляр с новым connection pool в lifespan
   - Для SQLite: используется общий экземпляр (с блокировкой)
5. **Улучшена читаемость кода** - зависимости явно указаны в сигнатурах функций роутов

**Файлы:**
- `miniapp/api/routes.py` - рефакторинг dependency injection
- `miniapp/api/server.py` - добавлены lifespan events
- `miniapp/api/main.py` - обновлена инициализация

**Архитектура:**
- Зависимости инициализируются в `lifespan()` при старте FastAPI
- Зависимости хранятся в `app.state.db` и `app.state.client_manager`
- Dependency functions (`get_db()`, `get_client_manager()`) получают зависимости из `app.state` через `Request`
- Все роуты используют `Depends()` для получения зависимостей
